## 2. Changes to the model made in this step

| Change | Why |
| --- | --- |
| **Audit moved inside `bp`** as Audit Service + Audit Hot Index + Audit Archive (WORM) | Step 4 note; the audit database is part of the designed solution (statement §3.6) |
| Notification providers renamed: **SMS Provider A** (local aggregator), **SMS Provider B** (AWS End User Messaging), **Email Provider** (Amazon SES), **Push Services** (FCM / APNs) | Step 11, ADR-016 |
| Added **Registro Civil (DIGERCIC)** | Step 7 |
| Interbank network renamed **Payment Network / BCE** (RPI / SIP / SPI, ISO 20022) | Step 8 |
| Added **Compliance Officer** (staff) | Users of the audit trail (Step 10) |
| "TBD" protocols replaced | REST / SOAP over Direct Connect, ISO 20022 / mTLS, Kafka, etc. |

### Consistency fix across steps

The **order of hops** was written two ways. It is now the same everywhere: **Edge (CloudFront + WAF) → API Gateway (Kong) → BFF → domain services**. Reasons: the gateway is the single entry point (C-04), and DPoP proofs must be checked on the first hop the client calls (Step 6). Step 4 (section 5 and 6) and Step 5 (section 1 diagram) were updated.

## 3. Rendering and export

1. Start Docker Desktop, then from the repo root (Git Bash):

   ```bash
   MSYS_NO_PATHCONV=1 docker run -it --rm -p 8080:8080 -v "$(pwd -W)/architecture:/usr/local/structurizr" structurizr/structurizr local
   ```

2. Open <http://localhost:8080>, pick a view in the diagram list.
3. Autolayout is on for every view. If a view looks crowded, turn autolayout off for that view (remove the `autolayout` line), drag elements, and the layout is saved in `workspace.json` (commit it).
4. Export each view as **PNG** (for the PDF) and **SVG** (zoomable) into `architecture/exports/`, named by view key, with the legend.
5. The layered security view (Step 12) is drawn separately in draw.io, as allowed by ADR-001.
